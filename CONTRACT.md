# Windows desktop

## Purpose and facilities
desktop-host: Configured Electron host with local assets and capture/navigation policies. Local-development status; the `configuration` requirement is optional.

## User inputs
Supply absolute webRoot and outputRoot, a lowercase custom scheme, appName, partition, modeEvent, exact serverOrigin and externalOrigins. Server origin must be secure except explicit loopback. External origins must use secure transport and contain no path or credentials.

## Artefacts and dependencies
Every implementation file maps to components/windows-desktop/ with its implementation/ prefix removed. `verification/result.mjs` writes and reads the aepm verification context and result files (the same protocol as video-calls' harness), so an application's Windows verification scripts need this component alone. SOURCE.md records each file's frozen source and line ranges; SOURCE.json records the pinned source hashes. tools.lock.json pins the tool versions. Policy/build checks use Node 26.5.0 and npm 11.17.0 only. examples/desktop contains an independent consumer and real dependency lock for Electron 45.0.0, electron-builder 26.15.3 and archive inspection.

## Provided interfaces
interfaces/contract.json is an OpenRPC 1.3.2 document for ae/desktop-host version 1.0.0: one method per exported function of desktop/src/main.cjs, policy.cjs, shell.cjs, desktop/scripts/build.cjs and verification/desktop.cjs, plus the functions of the returned policy (`Policy.*`) and shell (`Shell.*`) objects, with parameters and results as JSON Schema 2020-12 and the errors start, createPolicy, build and the verification helper throw. The visual output connector is ae/desktop-host version 1.0.0.

## Required interfaces
The `configuration` requirement is optional: the web root, output root, scheme and origins are the application's own values and can be passed in code to the build and runtime functions, so a design may leave the port unconnected. The configuration input connector is ae/windows-desktop-configuration version 1.0.0; interfaces/required-configuration.json is the JSON Schema 2020-12 document of its fields. Supply absolute webRoot and outputRoot, a lowercase custom scheme, appName, partition, modeEvent, exact serverOrigin and externalOrigins. Server origin must be secure except explicit loopback. External origins must use secure transport and contain no path or credentials.

## Integration
See INSTRUCTIONS.md for selection and configuration and suitability.json for the local-library profile. Call build with the generated web project and desktop/build/web. It runs npm run build:desktop with VITE_DESKTOP=1; caller owns APP_VERSION and VITE_APP_VERSION. Package that output as resources/web and pass its resolved absolute path to start. Include components/windows-desktop/desktop source in the packaged application and make Electron resolvable from that location. Electron is loaded only by start. Publish document.documentElement.dataset.mode and modeEvent before capture; unknown modes deny capture. See examples/consumer.cjs.

## Visual definition and connected examples
visual/definition.json is the component block. visual/examples/connected.json wires an illustrative configuration provider and consumer. visual/output/connected.svg and connected.png are generated by the shared format-1 renderer; consumers require neither that tool nor its checkout. visual/output/description.md supplies the text equivalent.

## Infrastructure
No remote service is provisioned by this component. Costs are unmeasured; no deployment is verified.

## Verification
Run npm test from the package root. In a private copy run npm ci --prefix examples/desktop --ignore-scripts --no-audit --no-fund, explicitly prepare Electron with node examples/desktop/node_modules/electron/install.js, then node scripts/package-consumer.cjs and node scripts/check-package.cjs. Packaging invokes the actual production web build helper and retains production desktop sources. scripts/check-package-rejection.cjs verifies relocated resources and rejects altered/missing scripts. No sibling application or personal assets are required.
The packager stages exactly main/shell/policy and the desktop verification helper beneath its own project. It checks every source/staging ancestor, rejects links and unexpected members before replacement, and compares staged bytes with originals. Home, temporary and dependency path protections remain intact.
Format-2 declarations run package and runtime checks under explicit execution authority. scripts/platform-check.cjs runtime launches the produced unpacked executable only on Windows x64 and terminates on its deadline; the parent installer contains the complete process tree. The child sets the runner-created context-directory/profiles/desktop path synchronously before Electron readiness, runs real window/assets/navigation/mode/capture assertions and writes the bound result. process-tree-terminated remains false/null and final profile cleanup remains pending for the parent. No installer is invoked. Windows runtime remains unverified on this Mac.
The capture assertion requires fake devices without a permission-success switch, focused synthetic input, successful player capture with stopped tracks, then an actual board transition and fresh interaction before denial. Unexpected board capture is also stopped before failure is reported.

## Scenarios and presentation
Only a trusted player main frame after interaction can capture microphone/camera. Board entry invalidates pending permissions. Downloads, screen capture, child navigation and unapproved external origins are denied. Assets resolve inside the supplied web root, including after relocation.

## Updates and removal
Patch updates use files-only migration. Caller-owned persisted preferences, desktop partitions and provider rooms are not deleted by removal. Remove generated source references when removing this component. Licence wording remains deferred.
